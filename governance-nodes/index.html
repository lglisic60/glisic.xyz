Governance Nodes

A single immutable smart contract for composable blockchain governance.

Most blockchain governance is built by writing custom smart contracts. A project wants voting, quorums, timelocks, delegation, vetoes, or upgrade rights, and the normal answer is to write and deploy a new stack of contracts, which means the governance logic lives in bytecode, and changing the rules means upgrading or redeploying the contracts that define them.

Governance Nodes takes a different approach. The Governance Nodes Contract (GNC) keeps the execution engine fixed and moves governance logic into state: a governance rule becomes data, stored inside Nodes. A quorum rule can be a Node. A timelock can be a Node. A veto can be a Node. A governor can be a Node that references the others. Governance systems can then be created, copied, forked, reused, and composed without writing a new contract every time, and a project can adopt another project's rule, fork it, and credit the lineage on-chain.

The GNC is deliberately small: one fixed Node schema, twelve conditional operators, four action types. The constraints are the point; they are what make the system understandable, auditable, composable, and eventually formally verifiable. And authority stays local: a Node can only edit itself, only through its own Clauses. There is no hidden global admin, no banlist, no freeze switch, no upgrade path. If safety machinery is wanted, it is built as Nodes, not hardwired above them.

The full technical specification is public: Governance Nodes Contract, Technical Specification, Draft v1 (May 2026). In its own words: about 80 to 90 percent of a full, comprehensive spec; buyer beware, it might still contain a hallucination or two. It is prepared for public implementation and open-source collaboration, and it is written for a builder to read front to back and then implement.
